# 计划 02:工具规模化与工具检索(Tool Scaling)

> 定位:定量实验 | 难度 ★★★ | 周期 4-6 周 | 产出:工具数量-选择准确率曲线 + 供给策略对比
> 对应课程子方向:工具管理

## 一、研究意义

MCP(Model Context Protocol)生态爆发后,一个智能体可挂载的工具数量从几个涨到几十上百个。但工具 schema 全部塞进系统提示会带来两个问题:token 成本线性增长;工具选择准确率下降("工具越多,模型越容易选错/重复造轮子")。dsh 以插件+MCP 管理工具,Deep Agents 已做"异步工具加载"(启动只加载定义),但**"上百工具时该怎么把工具供给模型"缺乏系统性的定量研究**。

本计划回答:harness 层的工具供给策略——全量注入、分类分组、向量检索 top-k、两阶段选择——在工具数量从 10 涨到 200 时,对选择准确率、误调用率、token 成本、端到端成功率的联合影响。这是 harness 工具管理子方向最接近"底层"的实证问题,结论可直接指导 dsh 插件生态的实践。

## 二、研究现状及实验室研究基础

- **协议与规范**:MCP 由 Anthropic 于 2024-11 发布,提供 tools/resources/prompts 三原语,已成为 dsh 与 deepagents 共同的外部工具标准;安全侧已有工具污染(tool poisoning)分析。
- **工程现状**:Deep Agents 的异步工具加载只解决启动阻塞,不解决"上下文里工具太多"的问题;dsh 插件按 Bundle 组合,本质上也是静态集合。
- **学术现状**:Function calling 规模化研究刚起步(工具检索/RAG over tool schemas 的零星工作),缺少"数量阶梯 × 供给策略"的系统曲线;这正是本科生可完成的增量贡献。
- **实验室基础**:仅需 Python + 任一 OpenAI 兼容 API + 向量库(FAISS/内存);工具集可从公开 MCP registry 与开源工具库收集,任务可程序化生成。

## 三、研究内容及研究计划

### 3.1 研究内容

1. **工具池构建**:收集/生成 200+ 真实工具 schema(优先从公开 MCP server 列表、LangChain 工具库抽取;不足则按领域模板合成并标注),保证语义多样、有近义干扰对(如 write_file vs edit_file)。
2. **四种供给策略**(模型与任务固定):
   - P1 全量注入(基线,所有 schema 进系统提示);
   - P2 分类分组(按领域分组,组名+一句话摘要常驻,详情按需展开);
   - P3 向量检索 top-k(任务描述嵌入,检索最相关 k 个工具);
   - P4 两阶段选择(第一轮让模型先从工具摘要目录里挑 5-10 个,再展开详情执行)。
3. **任务集**:400 个单步/双步工具调用任务("我需要把…,用合适的工具完成"),自动判定期望工具与参数。
4. **指标**:工具选择准确率、误调用率(选了不该选的)、参数正确率、每任务 token 成本、端到端成功率;主自变量为可用工具数量 N ∈ {10, 25, 50, 100, 200}。
5. **分析**:准确率-N 衰减曲线(各策略斜率);近义干扰对的混淆矩阵;检索召回上限对 P3 的约束;"多少工具以内全量注入够用"的实践阈值。

### 3.2 周计划(6 周)

- W1:工具池收集与清洗;任务集生成与校验(人工抽检 30 条)。
- W2:四种供给策略的统一实现(同一 agent loop,只换工具呈现层)。
- W3:小规模试跑(N=25)校准;修任务歧义。
- W4:全量实验(5 档 N × 4 策略 × 400 任务)。
- W5:分析与作图;消融(摘要质量对 P2/P4 的影响)。
- W6:撰写报告与"harness 工具供给实践建议"。

### 3.3 预期产出与验收标准

- 产出:工具池与任务集(可发布)、实验代码、准确率-N 曲线、策略对比表、实践建议清单。
- 验收:每格(策略×N)至少 80 任务;给出明确的实践阈值结论(如"N≤x 时全量注入不低于检索策略")。

### 3.4 风险与退路

- 风险:真实 MCP server 装配成本高 → 退路:schema 层研究,执行用 mock 实现,不影响结论。
- 风险:任务与工具池存在信息泄漏(任务描述直接复述工具名)→ 控制任务措辞与工具名解耦,并做同义改写。
