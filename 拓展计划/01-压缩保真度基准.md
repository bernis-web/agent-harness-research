# 计划 01:长会话压缩(Compaction)保真度基准

> 定位:定量实验 | 难度 ★★★ | 周期 4-6 周 | 产出:小型 benchmark + 压缩策略对比报告
> 对应课程子方向:上下文管理、复杂任务执行

## 一、研究意义

Compaction(压缩)是长时任务智能体不崩溃的关键机制:会话接近上下文窗口上限时,把历史摘要后重开新窗口。dsh 内置 compaction 模块,LangChain Deep Agents 用虚拟文件系统+子代理隔离实现类似目标,Claude Code 同样内置 auto-compact。

但现状是:**所有框架都在压缩,没有人系统测量过"压缩丢掉了什么"**。工程文章(Anthropic、Manus)描述了机制,却没有回答:朴素截断、全文摘要、结构化摘要、检索回填,各自会丢失哪类关键信息(任务边界?工具调用参数?早期约束?)、对端到端任务成功率影响多大、token 成本差多少。本计划构建一个可复现的小型基准,给出第一批定量答案,直接服务于"懂底层运行逻辑"的课程目标。

## 二、研究现状及实验室研究基础

- **机制来源**:Anthropic《Effective Context Engineering for AI Agents》提出 compaction/工具结果清理/外部记忆三件套;Manus 公开 KV-cache 友好实践;dsh 源码 `compaction` 模块(事件摘要重建,保留工具调用结构与任务边界);Deep Agents 走文件系统路线(状态外置而非摘要)。
- **学术空白**:检索增强领域有"lost in the middle"等上下文利用研究,但针对"harness 层压缩策略"的受控对比基本空白;A-MEM(NeurIPS 2025)等记忆论文只管写入与检索,不管会话内压缩。
- **实验室基础**:实验只需 Python + DeepSeek/OpenAI 兼容 API + deepagents(开源);任务可程序化生成与自动评分,单卡/无 GPU 即可完成,适合本科生科研实践条件。

## 三、研究内容及研究计划

### 3.1 研究内容

1. **长任务集构建**(约 20-30 个任务):多约束代码改造/多阶段写作/信息综合三类。关键设计——在任务早期埋入"延迟使用的约束"(如第 1 步给出"所有函数命名用 snake_case、第 7 步才检查"),使压缩造成的信息损失可被末端评分捕获。
2. **四种压缩策略实现**(控制模型与任务不变):
   - S1 朴素截断(保留最近 N 轮);
   - S2 全文摘要(LLM 自由摘要);
   - S3 结构化摘要(强制保留:任务边界、未完成 TODO、关键工具调用及其参数、用户约束清单——对照 dsh compaction 的设计);
   - S4 选择性保留+检索回填(压缩时仅保留骨架,细节写入外部文件,需要时按关键词取回——对照 Deep Agents 文件系统路线)。
3. **指标**:端到端任务成功率;关键约束召回率(埋点约束是否被遵守);token 总成本;压缩前后行为漂移(同一任务在压缩点前后的计划一致性)。
4. **分析**:哪种信息类别最易丢(约束/参数/边界/否定性指令);策略×任务类型交互;成本-质量帕累托前沿。

### 3.2 周计划(6 周)

- W1:读 deepagents 中间件与 dsh compaction 相关源码;定任务 schema 与埋点约束规范。
- W2:任务生成器 + 自动评分器(规则可程序化判定)。
- W3:四种策略实现(S3/S4 直接借鉴两框架源码设计)。
- W4:跑主实验(≥4 策略 × ≥20 任务 × 2 次重复)。
- W5:分析作图;补充消融(压缩触发阈值 70%/85%/95% 窗口占比)。
- W6:撰写报告与结论。

### 3.3 预期产出与验收标准

- 产出:benchmark 代码仓库 + 数据表 + 图(策略对比、帕累托前沿)+ 中文报告。
- 验收:每策略至少 20 任务 × 2 重复;结论能明确回答"结构化摘要是否显著优于全文摘要""文件外置路线的召回优势是否存在"。

### 3.4 风险与退路

- 风险:任务自动评分有噪声 → 退路:缩小为代码改造类任务(可测试判定)。
- 风险:长任务成本高 → 退路:用较小模型做主体、前沿模型做抽查校验。
