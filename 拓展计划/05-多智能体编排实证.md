# 计划 05:多智能体编排模式的实证研究

> 定位:定量实验 | 难度 ★★★ | 周期 4-6 周 | 产出:单/多智能体对比数据 + "何时值得多智能体"决策指南
> 对应课程子方向:多智能体协作、上下文管理

## 一、研究意义

"要不要上多智能体"是当前最有争议的工程问题:Anthropic 的多智能体研究系统(orchestrator-worker)宣称检索类任务显著提升;Cognition(Devin)却发表《Don't Build Multi-Agents》,主张上下文分裂是失败主因。双方都是立场文章,**缺少小规模、可复现的受控实证**。

Deep Agents 的动态子代理提供了现成实验台:六种编排模式(分类路由/并行扇出/交叉验证/迭代收敛/结构化输出/动态生成)与单智能体共享同一个 agent loop,模型、工具、提示全部可固定。本计划在统一任务集上测"单智能体 vs 各编排模式"的成功率/成本/时延,并专门测**上下文隔离的代价**(子代理看不到的信息如何影响结果),把行业口水战变成数据。

## 二、研究现状及实验室研究基础

- **编排框架**:LangGraph(图状态机)、AutoGen(对话式)、CrewAI(角色制)、MetaGPT(SOP 制);综述见 arXiv 2508.10146(七框架系统比较)。
- **协议层**:MCP(工具接入)与 A2A(Google 2025.4,跨厂商智能体互操作)互补;本计划聚焦应用内编排,协议互操作作为延伸。
- **争议焦点**:Anthropic(多智能体在信息综合类任务上优)vs Cognition(单智能体上下文一致性优);deepagents 教程给出六模式但无定量对比——实验空白明确。
- **实验室基础**:Python + deepagents(DynamicSubAgentMiddleware 现成)+ DeepSeek API;任务自动评分为主。

## 三、研究内容及研究计划

### 3.1 研究内容

1. **任务集**(三类 × 每类 15 题,共 45):
   - T1 信息综合(多源检索后交叉比对,天然适合并行扇出);
   - T2 代码生成+评审(适合交叉验证/迭代收敛);
   - T3 单链长推理(反例:理论上多智能体无优势)。
2. **对比配置**(模型/工具/系统提示全固定):
   - C0 单智能体(基线);
   - C1 并行扇出(N 个子代理独立做再汇总);
   - C2 交叉验证(生成者+批判者,论点传递);
   - C3 迭代收敛(生成-评审-修改循环 ≤3 轮);
   - C4 动态路由(模型自选模式)。
3. **上下文隔离代价实验**(核心创新):设计"关键信息不对称"任务——必要线索只在主代理上下文里(或只在子代理上下文里),测各模式的信息传递失败率;对比"子代理可见完整历史 vs 仅任务描述"两种委派协议。
4. **指标**:任务成功率(评分量表 rubric 自动化)、token 成本、时延(并行加速比)、信息传递失败率。
5. **分析**:模式×任务类型适配矩阵;多智能体的成本-质量边界;对 Cognition 论点(上下文分裂有害)与 Anthropic 论点(并行有益)分别给出支持/反驳条件。

### 3.2 周计划(6 周)

- W1:三类任务集与 rubric 自动评分器;deepagents 动态子代理机制精读。
- W2:五种配置实现;信息不对称任务设计。
- W3:主实验(5 配置 × 45 任务 × 2 重复)。
- W4:隔离代价实验;委派协议消融。
- W5:分析作图;错误归因(手动读 20 条失败轨迹)。
- W6:撰写报告与决策指南。

### 3.3 预期产出与验收标准

- 产出:任务集与评分器、实验代码、模式×任务适配矩阵、"何时多智能体"决策指南。
- 验收:每配置每类 ≥15 题 × 2 重复;决策指南以规则形式给出(如"信息综合且子任务独立→并行扇出;需要全局一致推理→单智能体")并有数据支撑。

### 3.4 风险与退路

- 风险:rubric 自动评分偏差 → 退路:T2 用可测试判定,T1/T3 人工双评抽样校准。
- 风险:并行时延受 API 限流干扰 → 时延指标只作参考,主指标用成功率与成本。
