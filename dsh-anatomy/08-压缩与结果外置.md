# 笔记 08|压缩(Compaction)与结果外置(Spill)

> 基于 commit `c291e7961a515f6d7af9304e7fd1d257929aef26`。核心材料:`docs/subsystems/compaction.zh.md`(238 行)、`docs/subsystems/spill.zh.md`、`packages/compaction/`(4 包)、`packages/spill/`(3 包)、`packages/spill/spill/src/types.ts:63/76`。术语表见笔记 01 §六。

## 一、机制作用:窗口装不下账本怎么办

笔记 04 的结论是:会话日志是唯一真源、只追加、永不改写。但模型上下文窗口有限——**账本完整**与**窗口有限**的矛盾,由两个独立机制化解:

- **compaction(压缩)**:把一段 surface 历史替换成一条摘要节点,**账本不动,遮蔽投影**;
- **spill(外置)**:超大工具结果全文落盘,上下文只留预览+定位指引——**账本记的是替换后的事件**,全文在模型上下文之外。

两者合起来构成 dsh 对"上下文管理"子方向的答案:压缩治"历史太长",外置治"单条太大"。它们都**不是** agent loop 的一部分,而是挂在账本之上的可选能力(能力 seam)。

## 二、代码走读

### 2.1 compaction seam:一个 SD、basic 后端、命令 Consumer

与 bash 同型:Service Definition `dsh-compaction`(`ctx.compaction`)、Service Provider `dsh-compaction-basic`(基于 tokenizer 的保留策略/阈值/摘要调用全归它)、Consumer `dsh-command-compact`(手动 `/compact` 命令)。接口**必然依赖 `dsh-session` 与 `dsh-llm`**(摘要事件用 `ContentBlock` 词汇、摘要调用走 `ctx.llm.stream()`)——这是"压缩"作为能力的耦合面(`docs/subsystems/compaction.zh.md:5-11`)。

### 2.2 三事件锁协议:崩溃安全的压缩事务

压缩经声明合并向 `SessionEventMap` 添加三种**仅日志**事件(log-only,绝不进 surface):

| 事件 | 载荷要点 | 作用 |
|---|---|---|
| `compaction/start` | `{turn}`(自动轮次号,手动为 `null`) | 获取**日志记录的锁** |
| `compaction/summary` | `summary` 安全投影 + `shadowedRange`/`shadowedSeqs`/`shadowedTokenCount` + `provider/model/usage` + `llmStreamCall` 标记 | 记录摘要、被遮蔽范围与模型调用 |
| `compaction/end` | `{turn, error?}` | 释放锁(`error` 记失败尝试) |

锁括住**整个**操作:先 `start`,再生成摘要、写 `summary` 与 `user/message` 替换,最后 `end`。**最后释放锁的含义**:中途崩溃表现为"有 start 无 end"的可检测遗留锁,而不是虚假声称完成的 `end`(`docs/subsystems/compaction.zh.md:30-38`)。**摘要本体不扩展 `SurfaceEventType`**——它是承载在另一条带 `surfaceOp: {op:'replace', startSeq, endSeq}` 的 `user/message` 上的;这是压缩对 surface 的**唯一**变更(`:21-25`)。

两个边界细节:活动的未匹配 start 会阻塞所有入口点;**较新 `session/end-seed` 之前的未匹配 start 是先前生命周期的陈旧证据,直接忽略**——与笔记 04 的种子边界机制严丝合缝。

### 2.3 surface 替换的位置语义

`CompactionResult.shadowedRange` 的注释值得整段读:`{start, end}` 是 **surface 位置跨度,不是数值 seq 区间**——前次替换把一条高 seq 的摘要节点落在旧区间的位置上之后,`start` 可能**大于** `end`;权威的被遮蔽集合是按 surface 序排列的 `shadowedSeqs`。加上笔记 04 讲过的"第 0 号系统节点不可覆盖、后续系统节点可被遮蔽",dsh 的投影层就有了完整的"替换 algebra"。

### 2.4 触发与时机:pressure / context-overflow / compactNow

`CompactionEngine` 三个动词:`compactIfNeeded(agent, trigger, signal)`('pressure' 常规压力 / 'context-overflow' 提供方确认溢出——**已确认的溢出可以比普通压力更激进**)、`compactNow(agent, signal)`(未达压力也强制缩减空闲会话,作为轮次间 agent maintenance 运行;无有效范围返回 `null` 不写日志)、`compactRegion(...)`(显式两端包含的 surface 范围)。**压力压缩挂在 `agent/pre-step` 瀑布、先于请求推导**——即每次模型请求前是压缩的唯一决策点。手动失败的错误码分类:`busy/cancelled/changed/summary/commit/persistence`,其中 `changed`/`summary` 保持表层不变仍闭合失败尝试并入账,`commit` 可能发生在部分变更之后,`persistence` 表示内存标记对已闭合但 flush 失败。

### 2.5 先剪枝,后压缩:toolResultPruner

compaction-basic 在选择范围前先调用**可选的 `ctx.toolResultPruner`**(`compaction-tool-result-pruner` 包),再用 `ctx.tokenMeter` 重新测量,**可以在不生成摘要的情况下推进 surface**——大工具结果先被"原位替换"成小版本(记录 `originalSeq`/`replacementSeq`/`callId`/`charsBefore`/`charsAfter`),不够再摘要。一个隐含约束:剪枝替换**保留工具调用/结果配对**——SD 导出 `toolPairingBalancedBefore/After(session, seq)` 供范围边界检查,区域边界保持配对但**不保持整个轮次**(过大轮次中较早关闭的步骤可以被压缩)。

### 2.6 spill:全文出窗,预览留窗

`spill` 组(3 包)的分工(`packages/spill/README.zh.md:31-35`):`ctx.spillStore` 存储服务(`spill/`)、本地文件后端(`spill-local/`)、**监听 `ctx.tools` 的结果策略**(`spill-policy/`)。

- **存储契约**(`packages/spill/spill/src/types.ts:63/76`):`SaveTextSpill{owner, source, suggestedName, content}` → `SpillRef`(locator + retrievalHint)。`suggestedName` 只是提示("经消毒成单个安全路径段——它是提示,永远不是路径");`SpillSource` 注释明说 **"descriptive provenance only, never access control"**(来源描述,绝不是访问控制)。
- **本地后端的安全细节**(`docs/subsystems/spill.zh.md:92`):写入 `<root>/session-<sha256(sessionId)>/<random>-<safeName>`,根目录私有(0700)延迟创建,写入用 `open(path, 'wx', 0o600)`——**排他创建 + 仅所有者可访问,防预置符号链接重定向**;`retrievalHint` 告诉模型在该路径上用 `read` 或 `grep`。
- **策略行为**:超过 `maxInlineBytes` 的纯文本最终结果被替换为"首尾预览 + spill 引用";**尽力而为——保存失败时保留原始内联结果,不把成功调用变成 isError**。
- **fork 语义**:fork 继承的 locator 不复制不转所有权;fork 后产生的新 spill 用子 session id 分组。

### 2.7 三层防线与 KV-cache 视角

把 dsh 控制上下文体积的手段排成序:①**spill-policy**(单条结果太大,执行时即外置——最早、最便宜);②**toolResultPruner**(历史里的大结果,压缩前先原位剪枝);③**compaction**(整段历史,摘要替换)。对 KV-cache(计划 07 的主题)的含义:压缩/替换=投影重算=缓存前缀失效,因此 dsh 的设计把"最破坏缓存的操作"(摘要替换)放在 pre-step 决策点且尽量让①②先行——**能不动账本投影就不动**;而 `compactNow` 明确作为"轮次间 maintenance"运行,天然落在缓存边界上。

## 三、压缩事务全景

```mermaid
sequenceDiagram
    participant P as pre-step 压力检查
    participant PR as toolResultPruner
    participant E as CompactionEngine(basic)
    participant L as Session 日志
    participant S as Surface 投影
    P->>PR: 溢出/压力 → 先剪大工具结果
    PR->>L: 原/新 tool/result 事件(保配对)
    PR->>P: tokenMeter 重测, 够了则结束
    P->>E: compactIfNeeded(trigger)
    E->>L: compaction/start{turn}(拿锁)
    E->>E: ctx.llm.stream() 生成摘要(llmStreamCall:true)
    E->>L: compaction/summary{summary, shadowedSeqs, usage...}
    E->>S: user/message{surfaceOp:replace}(唯一surface变更)
    E->>L: compaction/end{turn}(放锁; 崩溃=遗留start可检测)
    S-->>P: deriveMessages() 用新投影继续
```

## 四、设计权衡

1. **账本不动,投影可换**:压缩从不删除或改写事件,只追加标记与摘要、并在投影层遮蔽旧节点——"历史不可变"与"上下文有限"不是矛盾,只要把"模型可见"定义为**投影**而非**存储**(`docs/subsystems/compaction.zh.md:21-25`)。代价:被遮蔽事件仍占存储与重建成本。
2. **锁 = 事件对,不是互斥量**:并发控制用"先写 start 再写 end"的日志协议实现,崩溃语义自动正确(遗留锁可检测);较新 end-seed 之前的遗留锁直接忽略——**把事务协议建立在账本语义上**,不需要额外的锁服务。
3. **摘要走一次可重建的模型调用**:`llmStreamCall: true` 时必须附完整 `rawOutput`,该请求"可由日志 + 代码重建"——摘要本身也是账本可推导物,不是黑盒。
4. **spill 是"尽力而为"的降级而非保证**:保存失败保留原文(不失败化调用)、来源信息明确声明"非访问控制"——它优化的是"上下文信噪比",不承诺安全边界;真正的隔离边界在笔记 05 的沙箱与守卫。

## 五、与 Deep Agents 对比

| 维度 | dsh | Deep Agents |
|---|---|---|
| 哲学 | 摘要压缩 + 剪枝 + spill 三层,**投影遮蔽,账本不动** | 状态外置:虚拟文件系统 6 工具,中间产物落盘,窗口=工作内存 |
| 压缩 | compaction seam(可换后端),锁=事件对,pre-step 触发 | SummarizationMiddleware(教程提及);非独立可替换能力 |
| 大结果 | spill-policy(maxInlineBytes,预览+定位,retrievalHint 教模型取回) | 无对应机制(结果原样进上下文) |
| 剪枝 | toolResultPruner(压缩前原位替换,保工具配对) | 无 |
| 恢复语义 | 崩溃=遗留 start 可检测;fork 继承 locator 不转所有权 | checkpoint 重放,无事务标记 |
| token 计量 | `ctx.tokenMeter` 单例(压缩 seam 不拥有计价) | 无公开对应 |

最深的差异仍是笔记 04 那条主线的延续:deepagents 把"窗口装不下"外推为"把状态搬到文件系统"(粗粒度、无事件语义);dsh 把它内化为"账本之上的投影变换"(细粒度、每步可审计)。前者实现简单、直觉自然;后者换来压缩事务的崩溃安全、剪枝的配对保持、以及"摘要可重建"的取证能力。

## 六、读码才知清单(本篇增量)

1. **摘要本体不是 surface 事件**:三种 `compaction/*` 全部 log-only,唯一 surface 变更是那条带 `surfaceOp: replace` 的 `user/message`——"压缩"在 dsh 里是**投影操作**,不是"删历史"(`docs/subsystems/compaction.zh.md:21-25`)。
2. **`shadowedRange.start` 可以大于 `end`**:surface 位置与 seq 数值是两个维度,前次替换会让新节点带高 seq 落在旧位置——任何想自己遍历 surface 的工具都必须用 `shadowedSeqs`(surface 序)而不是 seq 区间(`CompactionResult` 注释)。
3. **遗留锁的"过期豁免"**:较新 `session/end-seed` 之前的未匹配 start 是陈旧证据,直接忽略——种子边界(笔记 04)在这里兑现了它的第二用途。
4. **压缩前先剪枝**:compaction-basic 的顺序是 pruner → 重测 → (必要时)摘要,`PruneResult` 记录每个替换的 `originalSeq/replacementSeq` 与字符数——**"能原位换小就不摘要"是默认策略**,摘要是最贵的最后手段。
5. **spill 的 `wx` + `0600`**:排他创建防符号链接预植,0700 目录 + 0600 文件防同机其他用户——本地后端把"防预植攻击"做到了 open flags 层(`docs/subsystems/spill.zh.md:92`)。
6. **spill 失败静默降级为不外置**:策略尽力而为,保存失败保留原始内联结果——上下文信噪比优化不改变调用成败语义。
