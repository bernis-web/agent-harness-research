# T2 验收文档索引（草案，全部拟定待会审）

## 本目录预定文件
- `public-cases.md` — 10 个编号公开用例（U01 至 U10），每个含：精确输入数据、可复现步骤、逐条断言。
- `hidden-groups.md` — 固定数据替换组：仅替换数据，**逐字复用**对应公开用例的步骤与断言，不新增判据。
- `mutation-map.md` — 3 条单要求变异，每条映射到公开条款编号，仅索引不实现。

## 判据规则（内部固定草案，非用户已冻结）
1. 公开 10 组逐组 PASS/FAIL；组内每条断言全部满足才 PASS。
2. 隐藏组逐组 PASS/FAIL，规则同上。
3. N/A / BLOCKED 不计 PASS；静态 UNRUN 不计分。
4. 成功标准：公开静态门槛满足 + 公开10场景全过 + 隐藏4组全过。
5. 变异杀伤仅评价验收校准质量，不混入产品评分。
6. 不使用旧 P1 评分，也不与旧 P2 混算。

## 边界（拟定）
- 未来仅 public-cases.md（及公开 spec）可作为任务输入；hidden-groups 与 mutation-map 不得进入产品工作区。
- 未来任务诊断修复已有 notes.py；交付 notes.py、README.md、CHANGES.md≤10 条；tests 文件集合与内容哈希不变。
- 本验收草案未执行任何产品验证或变异实验；文档静态核对不构成产品通过。

## 会审前提
以下均为待判项：用例数据、断言文本、隐藏组数量与替换值、变异条目。协调员会审后方可决定是否制作与执行；本 README 不包含执行计划。

## 用户明确的诊断修复与静态交付门槛

- 未来任务是诊断并修复预置的已有缺陷 `notes.py`，不是从零创建；不得修改评价器提供的 `tests/`。

- 上述是公开静态门槛，不新增第 11 个行为场景；未核对则记 UNRUN，不能据此宣称通过。
