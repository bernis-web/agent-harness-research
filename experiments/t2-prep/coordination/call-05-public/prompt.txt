## 1. 产品概述（拟定）
`notes.py` 为笔记 CLI，仅四个子命令：`add`、`list`、`search`、`export`。数据存储于单一 store 文件（拟定 JSONL），导出为 JSON 数组文件。核心链：同一 store 上先写入、再读回查询、再导出，且导出文件可经 `--store` 重载后继续以相同语义操作。

## 2. 判据总则
1. 全部行为归结为 R01–R12（§6）；评价用例必须可映射到这些 ID。
2. 公开用例共 10 个，编号 U01–U10；其具体固定步骤与数据由下一批 public-cases 文档提供，本规格不在此预先锁定其步骤或覆盖点。错误类公开用例每例只含一个错误原因，不涉及多故障叠加。
3. 隐藏用例仅替换输入数据（标题、正文、查询词、路径字面量），不得引入新命令、新流程或新的断言类型。
4. 非法输入（任何被拒绝的操作）不得改变既有数据：被拒命令执行前后，实际 `--store` 路径文件的原始 bytes 必须逐字节相同。属 R09。

## 3. 命令行接口（全部拟定）
统一形式：`python notes.py <子命令> [参数]`。
- `add --store <path> --title <t> --body <b>`：追加一条。三者均必填，值必须紧跟选项（`--opt value`，亦接受 `--opt=value`）。`--store` 无默认值，缺失→exit 2。
- `list --store <path>`：向 stdout 输出全部记录（R07 格式）。
- `search --store <path> --query <q>`：`--query` 必填；缺失→exit 2；值为空串→exit 2；值为纯空格→合法，不做 trim（拟定：仅对空白字符构成的查询按原样参与匹配）。
- `export --store <path> --out <path>`：写出 JSON 数组到 `--out`。`--out` 必填；目标已存在的普通文件→拒绝 exit 2，不触碰目标与 store。
- 位置参数一律不允许；未知子命令、未知选项、重复选项→exit 2。`--help` 不在核心判据内（拟定：打印用法，exit 0，不读 store）。
- 输出约束（固定于本草案）：`add` 与 `export` 成功时 stdout 为空且 stderr 为空；`list` 与 `search` 成功时 stderr 为空；任何失败时 stdout 为空且 stderr 恰为一行非空文本，文案内容不锁定（拟定格式见 §8）。

## 4. 存储格式与双格式识别（全部拟定，待会审）
- **JSONL 格式**：UTF-8 无 BOM 文本，每个物理行恰一个 JSON 对象（记录 schema 见 §5），行分隔符 `\n`；文件末尾可有恰好一个结束 LF，两者均合法。空文件合法（0 条记录）。仅含空白字符（含 `\r`）的行非法。拟定：按 `\n` 分行后对每行直接 `json.loads`，`\r` 属 JSON 合法空白，故 CRLF 行可解析；产品自身写出一律 `\n`。带 BOM 的文件按「格式非法」处理（明确拒绝，而非声称 UTF-8 解码失败），exit 3。
- **JSON 数组格式**：单个 JSON 数组，元素为记录对象；即 `export` 的输出格式。
- **识别规则（拟定）**：读取 store 时，取原始 bytes 按 UTF-8 严格解码后，`lstrip()` 后首字符为 `[` → 按 JSON 数组解析；否则按 JSONL 逐行解析。识别只看首字符，不做多次尝试回退。
- `add` 写入格式（拟定，待会审）：按识别出的格式以同格式写入——JSONL 追加一行；JSON 数组则整体读出、追加元素、整体重写。待会审的另一更简选项：`add` 遇 JSON 数组格式 store 直接拒绝 exit 2；两案取舍待会审，本规格不以任一案为已决。
- 写出语义使用 `json.dumps(..., ensure_ascii=False)`（拟定）；分隔符、缩进、尾换行均为拟定值（§10），本草案判据不锁定空白与键序的具体表现。

## 5. 记录 schema（固定于本草案）
- 记录对象恰有两个键：`"title"` 与 `"body"`，类型均须为 string；多键、缺键、类型不符→畸形。
- `title` 不得为空串、不得为纯空白（去首尾空白后为空即拒绝）；`title` 在 store 内唯一（精确逐码点比较）；`body` 允许空串。任一既有记录违反→整个 store 视为坏数据，exit 3。
- 孤立代理（unpaired surrogate）：命令行参数值中出现→exit 2；store 内容中出现（UTF-8 严格解码或 JSON 解析暴露）→exit 3。均不修改任何文件。
- 畸形 store（任一行/元素非对象、类型不符、非法 JSON、BOM、坏 schema）→整个命令失败，exit 3，不修改任何文件。

## 6. 需求 R01–R12（ID 固定，条款待会审）
- **R01 argv 语法**：§3 的子命令、选项、必填、位置与重复约束；违反→exit 2，不读不写 store。
- **R02 路径语义**：相对路径按进程 cwd 解析；绝对路径按字面使用；含空格、中文的路径须正常工作；`./`、`../` 及等价写法规范化后指向同一路径时视为同一路径（用于 R11 判定）。路径为空串→exit 2；父目录不存在→exit 3 且不得隐式创建目录（`add` 的 store 不存在且父目录存在时新建文件本身；`export` 的 `--out` 父目录不存在→exit 3）；读操作遇 store 不存在→exit 3（只有 `add` 可以新建 JSONL store）；路径指向目录→exit 3。
- **R03 字符串保真（独立公开条款）**：`add` 后读回的 title/body 与输入逐字符（逐码点）相同，含逗号、双引号、反斜杠、LF 与制表符（于 JSON 转义层面保存、读回还原）、全角字符与 emoji 等。`--title` 纯空白→拒绝 exit 2；title/body 首尾空白不剥离、原样保存。
- **R04 重复标题**：`add` 时新 title 与既有任一记录 title 精确匹配（逐码点相等，不折叠、不忽略大小写）→拒绝 exit 2，store bytes 不变。
- **R05 导出语义**：`export` 产出合法 JSON 数组文件，UTF-8 无 BOM；元素为按 store 顺序的记录。成功判定：对目标文件按 UTF-8 无 BOM 解码、JSON 解析后，得到的有序记录集合（含每条记录的键集合与字符串值）与 store 解析结果精确相等；不要求空白、键序或 `ensure_ascii` 的具体表现。JSONL store 仍须满足「每物理行恰一记录」。export 失败（含写入中途部分 I/O 失败）时，目标文件的存在性及其原始 bytes 须与执行前一致（不存在则仍不存在）；实现可使用标准库临时文件＋替换机制，并须清理残留临时文件；本判据仅在可正常清理的同目录、非并发、非崩溃环境下验收。故障注入不在本轮固定判据内，本规格不承诺无法验收的故障场景。
- **R06 查询（独立公开条款）**：`search` 大小写不敏感，对查询词与 title、body 均 `str.casefold()` 后做子串（`in`）判定；命中按 store 顺序输出，每条记录至多出现一次（去重）；无命中→exit 0，输出 `[]`（R07）。
- **R07 输出格式**：`list`/`search` 向 stdout 输出单个 JSON 数组（§4 序列化语义），顺序为 store 顺序；无记录/无命中输出 `[]`（拟定加一个尾 `\n`，判据按 JSON 解析后比较，不锁定空白）。stdout 除该数组外无其他内容。
- **R08 退出码与错误输出**：成功 0；argv/缺参/空查询/重复标题/空白标题/导出目标已存在/同路径等输入类错误 2；I/O、权限、store 不存在、目录路径、坏 schema、解码失败等环境与数据类错误 3。失败时 stderr 恰一行非空文本（内容不锁定），stdout 为空；成功时 `add`/`export` 的 stdout 与 stderr 均为空，`list`/`search` 的 stderr 为空。
- **R09 数据完整**：被拒操作不改变实际 `--store` 路径文件的原始 bytes（逐字节比较）；成功读操作不重写 store；任何命令不残留临时文件（§5/R05 允许的临时文件机制须清理）；崩溃中断一致性不在范围（§11）。
- **R10 `--store` 重载（独立公开条款）**：`export` 的输出文件可用 `--store` 指向它执行 `list`/`search`/`add`，语义与原 store 一致（同一记录集合、同样顺序与查询结果）；后续行为按 §4 识别规则与当时会审选定的写入方案执行。
- **R11 路径边界**：`export` 的 `--store` 与 `--out` 规范化（含 `./`、`../`、相对/绝对等价）后指向同一路径→拒绝 exit 2，不打开文件、不触碰任何文件。软链接、硬链接、悬空链接、权限模拟、并发、崩溃等别名场景全部明确不验收，不要求 `samefile`/`realpath` 之外的链接实现，也不据此判定。
- **R12 范围与交付约束**：产品交付物、依赖限制、tests/ 不可修改、协调材料隔离、验收环境（单进程、顺序执行、可正常清理的非崩溃环境）等约束如 §0、§10、§11 所列；本条为范围声明，不含行为判据。
