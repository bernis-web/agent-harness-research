# 运行器设计(P1 修订版 v2.1)

> 版本:2026-09-15-v2.1(依据审阅意见 R1/R3/R4/R5/R6 修订) | 状态:待用户复审后进入 P2。
> 建议模块划分沿用详细计划 §10 P2 表;本文件为实现设计,非代码。

## 1. 总体结构

单进程编排器 + 每次运行一个隔离工作目录 + 独立评估器进程。运行器职责:按冻结脚本下发六阶段消息 → 处理模型响应与工具调用 → S2/S4 末执行重启序列 → 记录 Event(含 operation 三态)→ 触发独立评估器探针与终评。模型适配器统一注入(P2 仅假模型;真实适配器 P3 前经授权接入)。

## 2. 四条件实施(唯一差异矩阵)

| 通道 | C00 | C10 | C01 | C11 |
|---|---|---|---|---|
| STATE.md(结构化状态) | 不挂载+写拒绝 | 有 | 不挂载+写拒绝 | 有 |
| run_tests 执行反馈 | 固定拒绝文案 | 固定拒绝文案 | 两套件真实结果(分开标注) | 同左 |

- 四组**均可读取** `tests_protected/` 与 `tests_self/` 全部源码(信息可见性不是变量);仅执行反馈按条件遮蔽。
- 状态通道字段模板与 2000 token 上限维持(先导值);C10/C11 的 STATE.md 写入在阶段末状态窗口开放,占用与超限处理如实记录;阈值若调整,冻结前统一调并重跑受影响先导,不按成绩挑选。

## 3. 阶段与重启序列(R1/B1/B3)

### 3.1 冻结序列与次序

```text
阶段断言(P2 测试 V-R1):1, 2, restart, 3, 4, restart, 5, 6
阶段开始(B1):stage_start 时同时发布 ①当阶段用户消息 ②当阶段版本受保护套件(suite_updated)
  ——任何模型行动之前,套件即与当前有效需求一致;不存在"模型已行动而套件仍用撤销语义"的窗口
阶段内:模型/工具事件…
阶段末(每阶段,B3):
  stage_end → score_recorded(私有评分:S1–S6 每阶段对冻结代码快照执行当前有效检查,结果永不回传)
  → eval_probe(仅 S3 末:缺陷基线;按需:事务快照)——S3 基线是额外前置观测,不替代阶段评分
  → [state_write 窗口(仅 C10/C11;窗口内仅 STATE.md 可写,任务代码写请求拒绝并记事件;
     窗口内模型调用与 token 计入预算)]
  → restart(仅 S2/S4 末;restart-1 后进入 S3,restart-2 后进入 S5)
```

受保护套件版本计划(与任务说明 §0.2 一致):初始占位 → S2 stage_start 安装初始需求套件 → S3 stage_start 替换为变更后语义套件 → S4 stage_start 追加边界测试 → S5/S6 保持 S4 版本。

- **阶段结束判定**:模型显式声明完成,或连续 2 次响应无新工具调用且无待决问题;运行器据此记 `stage_end`。
- **失败继续/终止**:阶段内测试不过、缺陷未修复**不终止**——任务允许带错推进(研究对象);终止仅限:限额触达(`limit_hit`)、适配器崩溃、安全违规(越权写/篡改受保护资产)。
- **不重播**:重启输入仅含 冻结任务背景 + 仓库现状说明 + 工具说明 + 当前阶段指令(+C10/C11 的 STATE.md 行);**不重发任何历史阶段消息**,过期命令语气不进入任务背景段(背景段为中性描述,见任务说明 v2 §0.3)。

### 3.2 重启输入生成

运行器从 TaskSpec 读取 `restart_base`(逐字冻结基串,见任务说明 v2.1 §PA.3/§PB.4)与 `condition_attachment`(C10/C11 唯一附加行),按唯一组装规则生成:最终消息 = restart_base + stage_messages[k](C10/C11 再追加附加行);禁止运行时拼接其他文本。

## 4. 状态通道与文件冻结(R4)

### 4.1 跨重启保留文件清单(冻结,写入 manifest)

| 条件 | 允许跨重启存在的文件 |
|---|---|
| 全部 | 任务源码目录内文件、`README.md`、`tests_self/**`、初始数据资产(`data/`、`examples/`,只读)、`tests_protected/**`(**运行器按版本保留/重建,不属于模型可写资产**) |
| 仅 C10/C11 | 以上 + `STATE.md`(唯一交接文件) |

可读/可写/保留三集合(与数据契约 TaskSpec 同步):`readable_paths` = 任务全部文件(含 data/、examples/、tests_protected/);`writable_paths` = 源码目录+README+tests_self/(工作阶段可写);`read_only_paths` = tests_protected/(及 C00/C01 的 STATE.md 路径);拒绝判定按路径集合,不依赖顶层文件名黑名单。

- **无状态组拒绝规则**:C00/C01 对 `STATE.md` 及任何**新增的顶层交接文件**(NOTES.md/HANDOFF.md/progress.md 等非任务资产路径)的写请求一律拒绝并记 `denied`;读侧因文件不存在而自然失败。C10/C11 写第二个交接文件同样拒绝。
- **信息残留边界(诚实声明)**:任务代码、注释、README、自编测试中的信息残留是可观测的设计边界——本实验**不声称实现"完全无记忆"**,只声称"实验指定的跨会话状态通道存在与否"。残留作为过程观测登记(如重启后首响应是否引用 README),进入敏感性分析而非静默删样本。

### 4.2 三层隔离的显式区分(R4.3)

| 层 | 机制 | 本轮承诺 |
|---|---|---|
| L1 实验工具路径权限 | 写工具白名单(writable_paths)+受保护/交接路径拒绝 | P2 实现,V3 验证 |
| L2 执行子进程的 OS 隔离 | 临时目录 cwd、环境变量清洗、进程级禁网、单次超时、衍生进程清算 | **部分能力**——普通子进程+进程组控制不是完整沙箱;不具备的能力(用户级隔离/系统调用过滤)诚实列为后续闸门,未验证前不执行真实生成代码 |
| L3 隐藏评估资产隔离 | 私有目录不挂载;评估器在自己启动的进程中运行 | 目录不挂载由配置保证(V3 验证);"被测不可信代码无法篡改评分环境"**不因评估器自启进程即视为已实现**——P2 仅用受信任人工样例验证评分逻辑,真实不可信代码执行由独立安全验收闸门阻止 |

- **评估器信任边界**:评分证据(隐藏测试结果、状态快照、行为探针)全部由评估器在**自己控制的进程与目录**内产生;评估器从运行器冻结的代码快照导入被测包,不读取被测代码可写目录中的任何文件作为评分依据。
- **P2 门禁**:仅假模型 + 人工合成样例;`isolation_profile` 未选定并按 §7 验收前,拒绝执行真实模型生成代码(报错,不降级)。

## 5. 工具接口(R3/R4)

- `read_files(paths)` / `write_files(entries)`:白名单校验;受保护路径(`tests_protected/`)只读,写→`denied` 事件;交接文件规则见 §4.1。
- `run_tests()`:执行 `protected_test_cmd` 与 `self_test_cmd`(unittest 固定命令,工作目录锁定;"cwd 外文件不可达"是 **待验证能力**(N3),以 V3 用例核验后方可作为已具备事实陈述),输出截断(4000 字符,尾部保留);C00/C10 返回 `{"status":"denied","message":"本条件不提供测试反馈"}`,不泄露退出码/计数/时长等任何暗示;被测代码通过其他途径探测试套件内容属于 L1/L2 防护对象,V3 用例覆盖。
- 无通用 shell 工具;`run_tests` 的输出按数据处理。

## 6. 缺陷基线与恢复观测(R5)

- **S3 末探针**(`eval_probe`,评估器进程):运行缺陷专属探针(PA:空行/逗号行;PB:乱序导入),判定 S4 开始前目标缺陷是否存在,结果不回传。`already_correct`(缺陷不存在)的运行不计入修复率分子分母,单独报告。
- **S4 消息**采用任务说明 v2 的"验证边界情境"措辞,不捏造历史异常。
- **修复率(统一判定,三文件一致)**:repair_success ⟺ S3 基线探针确认缺陷存在 ∧ **S4 末探针通过 ∧ S6 末探针仍通过** ∧ S4 与 S6 评分点未破坏此前通过且仍适用检查;S6 才通过的运行单列 `late_repair`(终态通过),**不计入 S4 持续修复成功**;分母=探针确认缺陷存在的运行(already_correct 单列)。
- **事务检查**(PB):导入失败前后状态快照相等 + 原树行为探针不变(不用"下次导入成功"判据)。
- **恢复效率(v1)**:阶段级——restart 后到首次阶段末评分确认有效进展的调用数/时间;动作级定位列为可选扩展(逐快照私有评估,不回传、耗时单列),本轮不实现。

## 7. 限额、续跑与故障注入(R6)

- 限额:每运行 模型调用≤60、工具调用≤120、墙钟≤30min、总token≤120,000(计量不可靠→可执行费用硬上限+manifest 注明);请求前预留最大输出预算;重试≤2 次并计入全部预算。限额与重启节点在 RunConfig 构造时归一化,冲突抛 `ConfigConflictError`(见数据契约 §2)。
- 续跑:operation 三态(intent/applied/checkpoint)+ operation_id + 快照哈希 + 评分幂等键;**intent 存在而无 applied = 执行状态未知**(B2):按 operation_id 核对结果文件+内容哈希+已提交评分记录+操作完成标记后再分类,不得直接认定未执行;不可证明重放安全的操作进 pending_verification,不自动重放。持久化顺序(可执行文件协议,无数据库):**结果文件写盘并 fsync → 完成标记 ops/<op>.done(含内容哈希)→ 事件日志追加**。残缺尾行丢弃标记。详见数据契约 §6。
- **故障注入(本机兼容)**:运行器内置故障钩子(环境变量 `HARNESS_FAULT=<point>[:<sequence>]` 触发 `os._exit(code)`),故障点覆盖 **before_effect / after_effect_before_applied / after_applied_before_checkpoint / score_persisted_before_log**(B2:必须含"副作用完成后、applied 写入前"这一实际位置,仅在事件落盘后注入不能证明该窗口已覆盖);不以 `kill -9` 为默认跨平台手段。
