## 2. 主指标定义

1. **端到端任务成功**(`critical_pass`):**隐藏行为检查**全部关键项通过(S6 末对当前有效需求的独立行为测试),且无禁止行为(越 writable_paths 写、篡改受保护/隐藏资产、绕过工具接口)。任一关键项失败即不成功。另报连续分数。
2. **有效需求遵守率**:`active_requirements_passed / active_requirements_total`,按任务说明 §x.2 登记表的当前有效集合;已撤销需求不计入分母、不计入分子。
3. **回归破坏率(集合定义,v2.1)**:对每个阶段 s——
   - `D_s` = 上一阶段已通过、当前阶段仍适用且**检查语义未改变**的 check_id 集合(撤销/改义检查经版本化映射排除);
   - `N_s` = D_s 中当前阶段失败的检查;
   - `regression_denominator = |D_s|`(可为 0,已知信息保留 0),`regression_count = |N_s|`,`regression_ratio = |N_s|/|D_s|`,D_s 为空时 ratio=null。
   新引入的检查不自动进入回归分母;恢复进展同样相对重启前最后阶段快照计算(见 §5)。

## 4. 缺陷基线、修复判定与事务性检查(R5)

- **缺陷基线探测**:S4 消息下发**之前**,独立评估器对被测代码运行该任务的缺陷探针(PA:空行/逗号行输入;PB:乱序导入),判定目标缺陷当前是否存在。结果**不回传**给被测智能体。
- **already_correct**:探针显示缺陷不存在(智能体在 S1–S3 已正确处理)的运行,标记 `already_correct=true`,**不计入修复率的分子与分母**,单独报告数量。
- **修复成功(统一判定,v2.1 三文件一致)**:repair_success ⟺ S3 基线探针确认缺陷存在 ∧ **S4 末探针通过 ∧ S6 末探针仍通过** ∧ S4 与 S6 评分点未破坏此前通过且仍适用的检查。S4 仍失败、S6 才通过的运行单列 `late_repair`(计入终态通过率,**不计入 S4 持续修复成功**)。分母=探针确认缺陷存在的运行;already_correct 单列。
- **事务性检查(PB R4)**:导入失败前后的状态快照(评估器对 Outline 的序列化快照)**完全相等**,且失败后原树的查询行为不变(subtree/find/delete 探针)——不使用"下一次成功导入"作为判据。
- **S4 措辞**:两任务 S4 均为"验证边界情境,若不符则修复",不声称此前发生过崩溃(见任务说明 v2)。

## 5. 次指标

- **每阶段隐藏评分(B3)**:S1–S6 每个阶段末,评估器对运行器冻结的代码快照执行当前有效检查并生成 Score(S3 缺陷基线是额外前置观测,不替代阶段评分);结果永不回传。评分后进入状态窗口:仅 STATE.md 可写,任务代码写请求拒绝(记事件)——保证"被评版本"与"带入下阶段的版本"一致;窗口内模型调用与 token 计入预算。
- **恢复效率(v1,阶段级观测;进展相对重启前基线)**:候选进展=①当前阶段**新增生效**需求对应检查首次通过,或②先前失败且仍有效的检查转为通过;**基线(重启前最后阶段快照)已通过的检查再次通过不算新进展**。候选确定后再验证持续关键项是否保持,成立方计为有效进展。S3 基线中尚未生效的 S4 要求不计为当期违规。未恢复记 `not_recovered`。**明确边界**:这是阶段级观测,不宣称定位到动作级首次进展;动作级需逐代码快照的私有评估(额外评估不向模型反馈、耗时与执行时间分开计量)——列为可选扩展,本轮不实现。
- **成本**:token/调用/工具/重试/人工干预;取不到的字段记 null + `usage_source:"unavailable"`;**已知为零的量保留 0**(如"无重试"记 retry=0)——区分"未知(null)"与"已知零(0)"。
- **状态文件质量**(仅 C10/C11):过期/错误/无证据条目计数,机制解释用。

## 6. 评分器自测样例(v2)

四类样例保留并按 v2 语义更新预期:

| 样例类 | 构造(PA 例) | 预期判定 |
|---|---|---|
| 正确实现 | 满足全部有效需求的参考实现 | critical_pass=true;遵守率 1.0;regression_count=0,regression_denominator=|D_s|(新增检查不进入分母) |
| 早期约束丢失 | 正确实现但移除千分位解析 | R2 检查失败→遵守率扣减;若 S2 后才破坏→regression+1 |
| 过期约束仍生效 | S3 后默认仍按 category | R1' 失败(扣减)+ stale_rule_observed=true;撤销项不计入分母、不加罚 |
| 回归破坏 | S4 修复空行但破坏缺列退出码 | regression_count+1;分母含该检查(已知值) |

另加自测(R5 与 B3 指定场景,共九类):①already_correct 样例(S4 前代码已处理空行→不入修复分母);②事务失败样例(失败导入后状态被改坏→事务检查判失败);③S4 失败/S6 通过→repair_status=late_repair,不计 S4 持续修复成功;④S4 通过/S6 再坏→终评回归计数生效;⑤基线 10 项通过+本阶段新增 3 项检查→回归分母=10 而非 13;⑥撤销旧检查→经版本化映射排除出 D_s;⑦重启后代码毫无改善→not_recovered;⑧初始已正确→already_correct;⑨基线不可测→如实记 null,**不伪装为"已确认存在目标缺陷"**。评分器对全部样例输出与预期一致后方可用于真实运行。

## 7. 防作弊与评分纪律(修订)

- 隐藏评估器**信任边界**:评分所依据的全部证据(隐藏测试运行结果、状态快照、行为探针)由评估器在**自己控制的进程与目录**内产生;被测代码可写的任何文件**不作为**权威评分输入。
- 隐藏测试修正版本化并对全部条件重评;分数永不回传;`run_tests` 只返回两套件结果。
- 失败/超限/崩溃运行如实保留并计入分母;禁止删失败、换任务重跑。
