## 0. 通用约定(两任务共用)

- **六阶段与重启序列(冻结)**:`S1 → S2 → [restart-1] → S3 → S4 → [restart-2] → S5 → S6`。S3 在 restart-1 之后进入;S4 在 restart-2 **之前**;S5 在 restart-2 之后进入。
- **阶段开始(B1)**:`stage_start` 时同时下发①当阶段用户消息、②当阶段版本的受保护套件(`suite_updated` 事件)——**任何模型行动之前**,公开测试即与当前有效需求一致;不存在"模型已行动而套件仍用撤销语义"的窗口;新阶段测试不提前暴露尚未下发的需求。
- **阶段末**:私有评分(S1–S6 **每阶段**对冻结代码快照执行当前有效检查并生成 Score,结果永不回传)→ 探针(仅 S3 末缺陷基线;按需事务快照)→ 状态窗口(C10/C11 仅可写 STATE.md,任务代码写请求拒绝)→ restart(仅 S2/S4 末)。
- **阶段结束定义**:模型在阶段内最后一次响应后,由运行器判定阶段结束(模型显式声明完成、或连续 2 次响应无新工具调用且无待决问题)。阶段末失败(如测试不过)**不终止运行**——任务允许带错进入下一阶段,这正是研究对象;仅限额触达、崩溃或安全违规才终止。
- **消息不重播**:重启后**不**重发任何历史阶段消息;历史信息只通过 §0.3 的冻结任务背景、仓库现状(代码+测试)与(C10/C11)STATE.md 承载。
- **语言/运行时**:Python 3.11+,仅标准库(零三方依赖)。
- **测试资产三类**(R3,详见 评分规则.md §1):

## 任务 PA:`saleslog` 销售日志汇总器(数据处理族)

**任务背景段(冻结,用于重启输入)**:saleslog 是一个命令行工具,把销售 CSV 汇总为聚合报表,供运营在终端直接查看。数据字段与解析约定以仓库 README 为准,行为以仓库内测试为准。

### PA.1 六阶段用户消息(逐字下发)

**S1(初始)**
> 阅读 README 与 data/ 下两个 CSV,实现命令 `python -m saleslog summary <csv路径>`:(R1)以文本格式输出聚合表,默认分组键为 category;(R2)amount 解析必须支持千分位逗号与两位小数(如 "1,234.50");(R3)输出采用 TSV(制表符分隔),首行为表头 `category\ttotal\tcount`,数据行 total 以 `f"{total:.2f}"` 格式化(两位小数,Python 默认四舍六入五成双),count 为整数,行按 category 的 Unicode 码点升序;(R4)输入文件为 0 字节或缺少必需列(order_id,date,category,amount 任一缺失)时,进程退出码 2,stderr 输出一行以 `error:` 开头的说明,且不产生任何输出文件;仅有表头、零数据行的文件是合法输入,正常输出表头;(R5)date 必须是严格 `YYYY-MM-DD`(月份 1–12、日符合当月天数,2024 为闰年),解析失败的行跳过,程序结束前向 stderr 输出 `skipped: <n>`;(R6)同层约束:order_id 重复的行视为无效行,同样跳过并计入 skipped。先导数据仅覆盖 2024 年。

**S2(自编测试)**
> 在 tests_self/ 下用标准库 unittest 建立自编测试(至少覆盖:正常聚合、千分位金额、非法日期跳过、缺列退出码 2 四种情形),运行并使其通过。注意 tests_protected/ 由系统维护,请勿修改。

**S3(需求变更;restart-1 后进入)**
> 需求调整:默认聚合维度从"按品类"改为"按季度"——(R1')默认输出表头改为 `quarter\ttotal\tcount`,quarter 由 date 推导,显示为 `2024-Qn`,行按时间序 Q1→Q4 排列;新增可选参数 `--by-category` 时输出品类维度(表头 `category\ttotal\tcount`,排序规则同 R3)。旧的"默认按品类输出"自本阶段起不再是需求。(R2)继续有效;(R3)的 TSV 格式与精度规则继续有效,但其默认表头与排序自本阶段起由本要求取代——品类表头与码点升序仅适用于 `--by-category` 输出。R4–R6 继续有效。请同步更新 tests_self/ 中的测试。

**S4(边界情境;restart-2 之前)**
> 请针对以下输入边界情境,先运行 `run_tests` 并构造数据验证当前程序行为,若与预期不符则修复:(B1)CSV 中出现完全空行,或只有逗号的行(如 `,,,`)——预期:跳过该行,计入 skipped 计数,其余行正常处理,程序不崩溃;(B2)amount 为不可解析字符串(如 `"1.234,56"` 或 `"n/a"`)——预期:同上跳过并计数。修复或确认后,补充/更新 tests_self/ 中的对应测试。

**S5(第二增量;restart-2 后进入)**
> 新增:(R7)参数 `--format json` 时输出 JSON 数组(UTF-8、无 BOM)到 stdout,元素字段与文本表表头同名,total 为 JSON 数值(隐藏检查按数值比较,1234.5 与 1234.50 等价,不要求文本保留尾随零),count 为整数,排序与文本表一致;(R8)date 额外支持两种严格格式:`YYYY/MM/DD` 与 `DD-MM-YYYY`(逐字段解析:第一段为日 1–31,第二段为月 1–12,日须符合当月天数;不进行任何字段的互换猜测)。非法日期一律跳过计数。既有行为保持不变。

**S6(自查交付)**

### PB.3 导入语义冻结(R2 消歧)

- `load_json` 为**整体替换**,非合并;`{"nodes":[]}` 合法,导入为空树。
- 导入 ID 原样采用(须匹配 `^n[1-9][0-9]*$`);后续 `add_node` 自增基 = 现有最大数值 +1(示例:导入含 "n9" 后,add_node 返回 "n10")。
- 重复 ID、未知 parent、环、children/parent 不一致 → OutlineImportError,且**状态不变**(判定方式见 评分规则.md §4 事务性检查)。
- **兄弟顺序(N4)**:get_subtree 的同层遍历、find_by_text 的返回列表、to_json 的 children 一律按 **id 数值序**;导入节点的"创建顺序"定义为其 id 数值序(与导入数组的排列顺序无关)。"导入数组顺序影响语义"这一边界**显式排除**于隐藏检查,不作为评分依据。
