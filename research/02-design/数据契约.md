# 数据契约(P1 修订版 v2.1)

> 版本:2026-09-15-v2.1(依据审阅意见 R3/R4/R6 修订) | 状态:待用户复审 | Python 3.11+ dataclass 契约,非实现。
> 原则:每条结果可追溯;**未知=null、已知零=0**(两者严格区分);合成示例标注 synthetic;不承诺 exactly-once 外部调用。

## 1. TaskSpec(任务级规格,公开部分)

```python
@dataclass(frozen=True)
class TaskSpec:
    task_id: str                          # "PA-pilot" | "PB-pilot"
    task_version: str                     # "PA-pilot@2026-09-15v2.1"(消息/约束/测试脚本变更即升版本)
    family: str                           # "data-processing" | "mindmap-logic"
    initial_repo_ref: str                 # 初始仓库模板提交/目录哈希(不含隐藏答案)
    stage_messages: tuple[str, ...]       # 六阶段逐字消息(v2.1 冻结版)
    restart_base: str                     # ★v2.1(N1):重启消息公共基串(逐字,以"[当前阶段指令]:"结尾);
                                          #   最终消息 = restart_base + stage_messages[k](+ 条件附加行)
    condition_attachment: str             # ★v2.1(N1):C10/C11 唯一附加行(STATE.md 说明);C00/C01 不追加
    task_background: str                  # 中性任务背景段(已含于 restart_base,字段保留供引用)
    readable_paths: tuple[str, ...]       # ★v2.1(N5):模型可读全部任务文件(含 data/、examples/、tests_protected/)
    writable_paths: tuple[str, ...]       # 模型可写白名单,如 ("saleslog/", "README.md", "tests_self/")
    read_only_paths: tuple[str, ...]      # ★v2.1(N5):只读:("tests_protected/",);C00/C01 另含 STATE.md 路径
    preserved_files: tuple[str, ...]      # 跨重启保留冻结清单(见运行器设计 §4.1;tests_protected 由运行器按版本保留/重建)
    state_file: str                       # "STATE.md";C00/C01 条件下写拒绝(按路径集合判定,非文件名黑名单)
    restart_after_stages: tuple[int, ...] # (2, 4)
    protected_test_cmd: str               # "python -m unittest discover -s tests_protected -p \"test_*.py\""
    self_test_cmd: str                    # "python -m unittest discover -s tests_self -p \"test_*.py\""
    limits: Limits                        # 任务级默认限额(见 §2 冲突归一化)
```

私有评分资产(隐藏测试、参考实现、需求-检查映射)不入本契约,仅以 `evaluator_version` 间接引用。

## 2. RunConfig(一次运行的最终配置)

```python
@dataclass(frozen=True)
class RunConfig:
    run_id: str                     # "PA-pilot__C11__r1__20260915T1030"
    task_version: str
    condition: str                  # C00/C10/C01/C11(首位=状态通道,次位=测试反馈)
    model_id: str | None            # 未确认前 None
    model_endpoint: str | None      # 仅名称
    sampling: dict                  # temperature/top_p/seed(seed_guaranteed=False 时如实记录)
    limits: Limits                  # ★归一化后的唯一生效限额(来源见 normalization)
    reset_after_stages: tuple[int, ...]
    state_token_cap: int | None     # 2000;仅 C10/C11 有效
    usage_metering: str             # "api_fields" | "client_estimate" | "unavailable"
    isolation_profile: str          # "local-tempdir-nonetwork-subprocess"(P2 冻结前不得执行真实生成代码)
    normalization: dict             # ★v2 新增:{"limits_source": "task_default"|"run_override",
                                    #             "conflicts": []}   冲突非空时构造直接抛错
```

**限额/重启冲突归一化(R6)**:RunConfig 由 TaskSpec(任务默认)+运行计划(覆盖项)生成;`reset_after_stages` 与 `limits` 仅允许来自其一——覆盖项与任务默认不一致时,**必须在 `normalization.conflicts` 中为空才允许构造**,否则抛 `ConfigConflictError`,禁止静默取一。

## 3. Event(JSONL 追加)

```python
@dataclass(frozen=True)
class Event:
    run_id: str
    stage: int                  # 0=初始化/恢复;1..6=阶段;7=终评
    sequence: int               # run 内严格单调递增,无空洞
    timestamp: str              # ISO 8601 带时区
    event_type: str             # 枚举见下(v2 增加 stage_end / suite_updated / op_* 三类)
    status: str                 # ok|error|timeout|denied|restarted|...
    artifact_ref: str | None    # 相对 runs/<run_id>/artifacts/ 的路径(不含 "artifacts/" 前缀)——v2 明确
    detail: dict                # 载荷;不含密钥
    usage: dict | None          # {"input_tokens","output_tokens","cached_tokens","source"};未知整块为 None
    operation_id: str | None    # ★v2 新增:跨崩溃可辨识的操作标识(评分/测试执行/快照等副作用操作)
```

`event_type` 枚举(v2):`run_start, stage_start, **stage_end**, model_request, model_response, tool_call,
tool_result, **suite_updated**, public_test_run, **eval_probe**(缺陷基线/事务探针,不回传), restart,
state_write, state_load, compaction_observed, limit_hit, run_end, score_recorded,
**op_intent, op_applied, op_checkpoint**(续跑三态,见 §6)。

**顺序不变式(v2.1,与运行器 §3.1 同步)**:阶段开始 `stage_start → suite_updated`(B1:套件在首模型行动前发布,四条件同时点)→ 模型/工具事件 → `stage_end` → `score_recorded`(S1–S6 每阶段私有评分)→ `eval_probe`(仅 S3 末缺陷基线;按需事务)→ `state_write`(状态窗口,仅 C10/C11)→ `restart`(仅 S2/S4 末);`tool_call/tool_result` 与 operation_id 配对。

**示例为节选**:示例事件标注 `"excerpt": true`(meta 级),不承担"无空洞"承诺。

## 4. Score(评分记录)

```python
@dataclass(frozen=True)
class Score:
    run_id: str
    stage: int
    evaluator_version: str          # 变更须全条件重评
    idempotency_key: str            # ★v2 新增:f"{run_id}:{stage}:{evaluator_version}"——重复写入幂等
    active_requirements_total: int
    active_requirements_passed: int
    critical_pass: bool
    regression_count: int
    regression_denominator: int     # ★v2:已知值,可为 0(此时比例理解为 null,由分析层处理)
    regression_ratio: float | None  # ★v2 新增:分母 0 时为 None——"0 检查项"是已知信息,保留 0
    stale_rule_observed: bool
    already_correct: bool | None    # v2(R5):仅缺陷相关评分有意义;探针确认缺陷不存在=true
    repair_status: str | None       # ★v2.1(B3):"s4_repaired"|"late_repair"|"not_repaired"|"already_correct"|null
    failure_category: str | None
    notes: str | None
```

**null/0 语义(v2,全局)**:未知或不可测 → `null` + 说明;**确定为零 → `0`**(如 retry=0、回归分母=0)。禁止用 0 冒充未知,也禁止把已知零写成 null。

## 6. 续跑与崩溃语义(v2.1,按 B2 重写;不承诺外部调用 exactly-once)

每个有副作用的操作携带 `operation_id`,事件三态 `op_intent → op_applied → op_checkpoint`;**持久化顺序是可执行文件协议**(无数据库):

```text
1. op_intent 事件落盘(含 operation_id 与操作类型)
2. 执行副作用:结果写入 ops/<operation_id>.result(写盘并 fsync)
3. 完成标记:写 ops/<operation_id>.done(含结果内容哈希)并 fsync —— 此即 op_applied 的持久形态
4. op_applied / op_checkpoint 事件追加到 events.jsonl
```

**intent 存在而无 applied = "执行状态未知"**(B2:同一日志状态对应两条路径——未执行,或已执行但 applied 未落盘)。恢复协议按 operation 类别的幂等依据分类处理:

| 操作类别 | 幂等依据(重放安全的原因) | 未知态处理 |
|---|---|---|
| 受保护套件更新 | 固定冻结脚本输出;原子替换(临时文件+rename),重跑产生逐字节相同结果 | 核对 ops/<op>.result 内容哈希与期望哈希:一致→补 checkpoint;不一致/缺失→重放(安全) |
| 代码/状态快照 | 目标目录不可变快照,一次性写入 | 同上(内容哈希核对) |
| 缺陷基线/事务/阶段评分探针 | 独立一次性工作目录中可重复评估;结果不回传 | 重放(评估可重复);结果以 <op>.done 的哈希核对 |
| score_recorded | idempotency_key(run_id:stage:evaluator_version)去重 | 先查 scores.jsonl 是否已有该键:有→补 checkpoint;无且 .result 存在→落分;否则重评 |
| 模型 API 请求 | **不可重放**(可能重复计费) | 未收到完整响应→`pending_verification`,不自动重发,列入运行报告待人工核对 |

崩溃窗口与恢复行为(P2 故障注入须逐项覆盖,HARNESS_FAULT 点见运行器设计 §7):

| 崩溃点 | 日志状态 | 恢复行为 |
|---|---|---|
| 执行前(before_effect) | 仅 intent | 未执行→按类别重放(幂等)或 pending_verification |
| 副作用完成后、applied 写入前(after_effect_before_applied)★B2 | 仅 intent;**.result 已存在** | 按上表核对哈希:一致→补 op_applied/checkpoint(**不误称未执行、不盲目重放**);缺失→按类别处理 |
| applied 后、checkpoint 前(after_applied_before_checkpoint) | intent+applied | 补记 checkpoint |
| score 落盘后、后续日志未完成(score_persisted_before_log) | score 已在 scores.jsonl | 幂等键去重,不重评;补齐日志 |

events.jsonl 末行残缺:丢弃残缺尾行并记 `run_start(status=resumed, detail.torn_tail=true)`,sequence 从最后完整行接续。

```text

├── manifest.json      # RunConfig 落盘,启动时写,不可变
├── events.jsonl
├── artifacts/         # snapshot_s{n}/、suite_s{n}/、probe_*.json、state_after_s{n}.json
├── scores.jsonl
└── ops/               # ★v2:operation 意图/结果哈希记录(续跑对账用)
```
